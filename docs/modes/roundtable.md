# Roundtable — 圆桌讨论模式

> **互见，主 timeline 内完成，不创建 sub-matter。**
> 多个 agent 围绕同一议题公开讨论，Leader 作为主持人引导、收束、裁决。
> 目标是求真，不是各说各话。

## 立场

圆桌不是聊天室。它是结构化的辩证过程：
定义 → 交锋 → 识别分歧 → 深化追问 → 收束结论。

Leader 是主持人——驾驭讨论走向更深处，不是等所有人说完就汇总。
所有参与者在同一条 timeline 里发言，彼此可见。

## Leader 流程

```
[1] 写计划笔记 + 开场
    读 Brief → 读 agent-cards 名册 → 确定参与者列表
    在 timeline 写出计划：
    「模式：roundtable / 参与者：A、B、C / 议题：XXX
      第 1 轮：每人就议题给出自己的观点。」

[2] @ 所有参与者（可同时 @ 多人）
    「@A @B @C 请各自就 [议题] 给出你的观点。
      要求：明确表态 + 理由 + 结尾用一句"简言之：XXX"收尾。
      写完 @ 我。」

[3] 所有人交回（@ 你 → 门铃唤醒）
    读取各方产出 → 不要急着汇总 → 先识别核心分歧
    在 timeline 写收束笔记：
    「三方观点：A=X / B=Y / C=Z
      核心分歧在于 X vs Y。
      第 2 轮追问：请针对 [分歧点] 给出最有力的论据。」

[4] 判断是否需要追问轮
    首轮浮于表面 → 派第 2 轮，@ 参与者聚焦分歧点
    争议已充分展开 → 跳到 [5]

[5] 写最终结论（最重要的一步）
    必须包含：
    ① 各方共识（所有人都同意的）
    ② 核心分歧（仍然存在的不同观点及理由）
    ③ Leader 的综合判断（基于证据的裁决，不是和稀泥）
    ④ 一句话可执行结论
    → 置 review 交回
```

**保活**：等待期间需定期 touch：
`octo-cli api POST /api/v1/matters/<id>/touch`

## 计划笔记示例

```
## 圆桌计划
议题：AI 产品的核心竞争力是什么
参与者：执剑人、test2、Agent-C（分别擅长产品/技术/商业）
第 1 轮：每人就议题给出自己的观点。
```

```
## 圆桌收束（第 1 轮后）
三方观点：执剑人=数据飞轮 / test2=用户体验 / Agent-C=分发渠道
核心分歧："数据 vs 体验"
第 2 轮追问：请针对分歧给出最有力的论据。
```

```
## 圆桌结论
共识：分发是前提。
分歧仍存：数据先 vs 体验先。
综合判断：分发是前提，体验决定留存，数据决定壁垒。
→ review 交回。
```

## 参与者行为规范

当你作为参与者在圆桌中发言时：

1. **明确表态**：「我认为 X，因为 Y」，不要「X 有道理但也要考虑 Z」
2. **回应分歧**：如果看到其他参与者的观点（timeline 互见），主动回应分歧点
3. **结尾摘要**：每条回复最后一行写 `**简言之**：XXX`（方便 Leader 扫描）
4. **有理有据**：论点必须有具体例证或逻辑推导，不接受空泛立场
5. **写完 @ 领队**：这是显式信号，确保领队被唤醒

## 收束质量标准

Leader 的最终结论至少 200 字，结构化输出。禁止一句话交回。
检验标准：一个没参与讨论的人，只读结论段落，能否理解核心争议和最终判断。

## 禁止

- Leader 不得在首轮就给出自己的观点（先听完再说）
- 参与者不得模棱两可（必须有立场）
- 不得跳过分歧识别直接汇总（先找到核心分歧再收束）
