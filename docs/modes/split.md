# Split — 分头干模式

> 任务拆成互不相关的子块，各 agent 独立完成自己的部分，互相看不到。
> Leader 最后汇总。

## 立场

Split 适用于任务可以干净地分区的场景——各块之间没有依赖、不需要讨论。
每个 agent 只看到自己那块的 Brief，对其他块一无所知。

## Leader 流程

```
[1] 读 Brief，规划分区
    ├─ 判断任务能否干净分割
    ├─ 不能分割 → 考虑用 roundtable（需要讨论）或 solo（不需要拆）
    │
[2] 派子任务（所有子任务可同时派出）
    ├─ 每个子任务的 description 只包含该分区的信息
    ├─ 不要在子任务 description 里提及其他分区（互盲原则）
    │
[3] 所有子任务交回
    ├─ 读取每个子单的产出
    ├─ 检查各块之间是否有冲突或重叠
    │
[4] 汇总
    ├─ 合并各块产出为一个完整的交付物
    ├─ 如果发现冲突 → 在汇总中标注并给出 Leader 的裁决
    └─ 置 review 交回
```

## Brief 应包含

- 任务的整体描述
- 分区建议（可选——Leader 可以自己判断怎么分）
- 各分区的边界说明

## 禁止

- 子任务之间不得互相引用（互盲）
- 不得让子任务自己决定要不要看其他子任务的产出
